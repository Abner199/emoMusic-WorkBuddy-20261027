# 心音 EmoSong · 基于人脸情绪识别的歌曲推荐系统

> HTML5 + CSS3 + JavaScript + **Vue 3**（无构建步骤，`<script>` 直接引入）
> 情绪识别：**浏览器本地推理**（face-api.js / TensorFlow.js），画面不出本机
> 音乐：**8 首离线本地曲目** + **Apple iTunes Search API 在线试听（30 秒）**

---

## 一、快速开始

### 方式 1：双击脚本（推荐）

```
双击 start.bat        # Windows
```

脚本会自动寻找本机 Python 并启动静态服务器，然后打开 `http://127.0.0.1:8787/`。

### 方式 2：手动启动任意静态服务器

```bash
# Python 3
python -m http.server 8787
# 或 Node
npx serve -l 8787
```

然后浏览器访问 <http://127.0.0.1:8787/>

> ⚠️ **不要直接双击 index.html**：`file://` 协议下摄像头（`getUserMedia`）会被浏览器禁用，
> 模型权重的 `fetch` 也会被跨域策略拦截。必须通过 `http://localhost` 访问。

### 首次打开会发生什么

1. 加载 3 个本地模型（约 880 KB）：TinyFaceDetector / FaceExpressionNet / FaceLandmark68；
2. 后台解码并分析 8 首本地音频（BPM / 调式 / 能量 / 明亮度），约 3~8 秒，结果会缓存到 localStorage；
3. 之后「开启摄像头 → 自动识别 → 自动生成歌单 → **自动播放第一首**」即可。

## 二、功能清单

| 能力 | 说明 |
|---|---|
| 实时摄像头 | `getUserMedia` 逐帧识别，约 6 fps，画布实时绘制人脸框 + 68 关键点 |
| 上传图片 | 点击选择或**直接拖拽**到取景框，静态高精度识别；下方附 **7 种情绪演示人脸画廊**（高兴/悲伤/愤怒/惊讶/恐惧/厌恶/平静），点击即测 |
| 打开视频 | 选择本地视频文件，边播放边逐帧识别，可暂停/继续 |
| 拍照识别 | 摄像头取当前画面冻结为静态图，再走高精度识别 |
| 情绪可视化 | 7 类概率条形图、主导情绪环形进度、情感环（Russell）散点 + 历史轨迹 + 目标点 |
| 推荐策略 | 智能 / 同频镜像 / 情绪修复，切换即时重排 |
| 双曲库 | 本地 8 首 + 在线 iTunes 试听，可关闭在线 |
| 本地导入 | 可导入自己的 mp3，同样在本地做声学分析后参与推荐 |
| 播放器 | 底部常驻播放条：进度、音量、下一首、自动连播 |
| 自动播放 | **识别出情绪、歌单生成后立即自动播放第一首**；情绪变化 → 歌单与音乐自动切换。可随时用「识别后自动播放」开关关闭；若被浏览器拦截会出现一键「点击继续播放」；手动暂停后 30 秒内不再自动打断（点选新的人脸会立即恢复播放） |
| 可解释性 | 每首推荐显示得分与推荐理由，悬浮显示五因子拆解 |

## 四、算法要点（详见 `docs/算法说明.md`）

**情绪识别（四层融合，全本地）**

1. `TinyFaceDetector` 检测人脸框与 5 关键点；
2. `FaceExpressionNet` 输出 7 类表情 softmax 概率 `p_cnn`；
3. 68 点 landmark 计算 6 个尺度归一化几何特征（嘴角上扬、张口度、眉眼距、内眉抬升、EAR、嘴宽比），
   经线性判别 + softmax 得几何先验 `p_geo`；
4. 对数线性贝叶斯融合：`log p ∝ (1−λ)log p_cnn + λ log p_geo`，λ=0.22；
5. 质量门控（人脸占比 / 拉普拉斯清晰度 / 偏航）+ 置信度自适应 EMA 平滑；
6. 按 Russell 情感环加权得到 `(valence, arousal)`。

**歌曲推荐（四阶段）**

1. 目标决策：镜像 / 修复（向修复锚点迁移 62%）/ 智能（valence<−0.15 转修复）；
2. 五因子打分：`0.40·S_va + 0.22·S_emo + 0.18·S_rhythm + 0.11·S_pref + 0.09·S_quality`；
3. 本地曲目的 `valence/arousal` 来自**真实声学分析**（FFT → 谱质心 / RMS / 自相关 BPM / Krumhansl 调性）；
4. MMR 重排：`argmax[λ·S − (1−λ)·maxSim]`，λ=0.78，避免同质化。

## 五、数据与版权说明

- **本地曲目**：来自 SoundHelix 公开示例音频（算法生成音乐，免费用于测试与教学），随项目离线提供，
  因此断网也能完整演示推荐与播放。
- **在线曲目**：Apple iTunes Search API 公开接口，返回的是**官方 30 秒试听片段**，不下载、不存储，
  仅用于演示；正式商用需替换为自有授权曲库。
- **人脸数据**：只在浏览器内存中处理，不写磁盘、不发网络请求。可用 DevTools → Network 验证。

## 六、常见问题

| 现象 | 原因与处理 |
|---|---|
| 点「开启摄像头」无反应/报错 | 必须 `http://localhost` 或 `https` 访问；检查浏览器摄像头权限 |
| 一直「模型加载中」 | 确认 `assets/models/` 下 6 个文件齐全（3 个 json + 3 个 shard1） |
| 识别不到人脸 | 光线不足 / 人脸过小 / 侧脸；界面右下角会给出质量提示 |
| 在线歌曲搜不到 | iTunes 接口有频率限制（约 20 次/分钟），稍等重试；或关闭「在线试听」 |
| 分析进度一直是 0/8 | 浏览器不支持 `decodeAudioData`（极老版本），或音频文件缺失 |
| 第一次推荐很慢 | 在线检索需并发请求 2 个区商店，之后同关键词走内存缓存 |

## 七、可扩展方向（课程实训建议）

1. 用 MediaPipe FaceMesh 替换 68 点模型，增加头部姿态（俯仰/偏航/滚转）抑制；
2. 增加「个人中性基线校准」，用录制的中性片段求每位用户的几何均值，提升个体适配；
3. 引入聆听反馈（跳过/收藏）在线更新 `S_pref` 权重，做成 Bandit 式的探索-利用；
4. 把推荐理由导出为 CSV，做 A/B 对比实验（镜像 vs 修复的听感满意度）；
5. 增加多人场景：取画面中面积最大的人脸作为主情绪，其余做加权共识。
