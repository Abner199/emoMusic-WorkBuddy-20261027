# 心音 EmoSong —— 算法设计说明

> 系统定位：完全在浏览器本地完成「人脸检测 → 表情识别 → 情绪量化 → 情感匹配选曲」的闭环，
> 不上传任何画面，也不需要云端推理服务。歌曲侧同时支持**离线本地曲库**与**在线试听接口**。

---

## 一、总体架构

```
                    ┌──────────────────────────────────────────────┐
   采集层            │  摄像头 / 上传图片 / 打开视频 / 拍照（截图）    │
                    └───────────────────┬──────────────────────────┘
                                        │ 帧（HTMLVideoElement / Image）
                    ┌───────────────────▼──────────────────────────┐
   情绪识别层        │ L1 TinyFaceDetector   → 人脸框 + 5 关键点     │
   (本地推理)        │ L2 FaceExpressionNet  → 7 类 softmax 概率     │
                    │ L3 68 点几何先验       → 6 特征 + 线性判别     │
                    │ L4 对数线性贝叶斯融合   → 融合概率            │
                    │ L5 质量门控 + EMA 时序平滑                     │
                    └───────────────────┬──────────────────────────┘
                                        │ (valence, arousal, 7 类概率)
                    ┌───────────────────▼──────────────────────────┐
   推荐决策层        │ S1 目标情绪决策（镜像 / 修复 / 智能）          │
                    │ S2 五因子加权打分                             │
                    │ S3 MMR 多样性重排                             │
                    └───────────────────┬──────────────────────────┘
                                        │
                    ┌───────────────────▼──────────────────────────┐
   曲库层            │ 本地曲库（Web Audio 解码 + DSP 声学分析）      │
                    │ 在线曲库（iTunes Search API，30s 试听）        │
                    └──────────────────────────────────────────────┘
```

## 二、情绪识别算法

### 2.1 L1 人脸检测：TinyFaceDetector

- 结构：Tiny-YOLO 风格的单阶段锚框检测器（深度可分离卷积堆叠 + 多尺度输出），权重约 190 KB。
- 输入：224×224（视频实时）或 416×416（静态图片，精度优先），必须为 32 的整数倍。
- **多尺度阶梯**：静态图识别时按 `416 → 608 → 320 → 224` 依次尝试，直到检出——
  特写大脸（人脸占比 >70%）在 416 下常检不出，远景小脸在低分辨率下也会漏检，阶梯化后均可覆盖。
- 输出：人脸框 `(x, y, w, h)`、置信度 `score`、5 个关键点（左右眼、鼻尖、左右嘴角）。
- 阈值：`scoreThreshold = 0.42`，低于阈值视为「无脸」，触发平滑衰减而非直接清零。

### 2.2 L2 表情分类：FaceExpressionNet

- 结构：VGG 风格轻量 CNN（conv 3×3 堆叠 + max-pool + 全连接），输入 64×64 灰度人脸。
- 输出：7 类 Softmax —— `neutral, happy, sad, angry, fearful, disgusted, surprised`，记作 `p_cnn(c)`。
- 该分支负责**纹理级**证据（眼周皱纹、鼻唇沟、口型），对光照与角度相对鲁棒，但对个体差异敏感。

### 2.3 L3 几何先验：68 点特征 + 线性判别

由 `FaceLandmark68Net` 得到 68 个语义点（iBUG 约定），计算 6 个**尺度归一化**几何量（全部除以瞳距 `io`，因此与人脸远近无关）：

| 特征 | 计算方式 | 语义 | 中性均值 / 尺度 |
|---|---|---|---|
| `smile` 嘴角上扬度 | `(口内中心 y − 嘴角中心 y) / io` | 微笑强度 | 0.118 / 0.075 |
| `mouthOpen` 张嘴度 | `dist(62,66) / 嘴宽` | 张口、惊呼 | 0.06 / 0.05 |
| `browRaise` 眉眼距 | `(睑上缘 y − 眉中心 y) / io` | 抬眉、惊讶 | 0.255 / 0.045 |
| `innerBrowUp` 内眉抬升 | `(内眼角 y − 内眉 y) / io` | 悲伤、恐惧 | 0.145 / 0.035 |
| `eyeOpen` 眼睛开合 EAR | `((d37,41 + d38,40) / 2) / d36,39` 双侧平均 | 睁眼程度 | 0.31 / 0.06 |
| `mouthWide` 嘴宽比 | `嘴宽 / io` | 咧嘴 / 抿嘴 | 0.72 / 0.12 |

先做 z-score 标准化 `z = (f − μ) / σ`，再送入 7 个线性判别函数（系数可解释、可调）：

```
happy     =  2.10·z_smile + 0.55·z_mouthWide + 0.25·z_eyeOpen − 0.90
sad       = −1.90·z_smile + 1.55·z_innerBrowUp − 0.45·z_mouthWide − 0.30·z_eyeOpen − 0.75
angry     = −0.85·z_smile − 1.35·z_browRaise + 0.85·z_mouthWide − 0.45·z_mouthOpen − 0.55
surprised =  1.85·z_mouthOpen + 1.45·z_browRaise + 0.95·z_eyeOpen + 0.30·z_mouthWide − 1.05
fearful   =  1.15·z_mouthOpen + 0.95·z_browRaise + 0.85·z_innerBrowUp + 0.60·z_eyeOpen − 0.50·z_smile − 1.15
disgusted = −0.70·z_smile − 1.10·z_browRaise + 0.70·z_mouthWide + 0.35·z_innerBrowUp − 0.85
neutral   =  0.55 − 0.75·max(happy, surprised, |sad|, |angry|)
```

经 `softmax(T = 1.15)` 得到几何先验 `p_geo(c)`。几何分支负责**结构级**证据，对 CNN 的抖动形成交叉约束。

### 2.4 L4 对数线性贝叶斯融合

两类证据在概率空间的加权几何平均（等价于对数域的线性组合）：

```
log p(c) ∝ (1 − λ)·log p_cnn(c) + λ·log p_geo(c),    λ = 0.22
p(c) = softmax[ log p(c) ]
```

- `λ` 偏小 → 以 CNN 为主导，几何先验只做「轻推」，避免规则过硬导致误判。
- `λ = 0` 时退化为纯 CNN；`λ = 0.5` 时两者等权（可在 `EmotionEngine` 构造参数中调整）。

### 2.5 L5 质量门控 + 时序平滑

**质量分**（用于提示与置信度惩罚）：

```
Q = s_face · s_yaw · (0.35 + 0.65 · s_blur)
s_face : 人脸宽 / 画面宽 ≥ 0.28 → 1；0.18~0.28 → 0.85；< 0.18 → 0.55
s_yaw  : |鼻尖 x − 两眼中心 x| / io ≤ 0.30 → 1，否则 0.7
s_blur : 人脸灰度裁剪 64×64 → 拉普拉斯方差 / 220，截断到 [0,1]
```

**EMA 平滑**（逐类独立）：

```
α = clamp(0.42 × (0.55 + 0.9 · max_c p(c)), 0.18, 0.72)
p̂_t(c) = α·p_t(c) + (1 − α)·p̂_{t−1}(c)   ，再归一化
```

置信度高时更新更快（跟手），置信度低时更保守（抗抖）。丢失人脸时按 `0.82/0.18` 缓慢回归均匀分布，避免情绪瞬间跳变。

### 2.6 主导情绪与置信度

```
dominant = argmax_c p̂(c)
margin   = p̂(dominant) − p̂(second)
confidence = clamp( (0.65·p̂(dominant) + 0.35·min(1, margin/0.35)) · (0.6 + 0.4·Q), 0, 1 )
```

### 2.7 情绪 → 情感环坐标

按 Russell 环形模型，对 7 类概率做加权质心：

```
valence = Σ_c p̂(c) · v_c      愉悦度 ∈ [−1, 1]
arousal = Σ_c p̂(c) · a_c      唤醒度 ∈ [−1, 1]
```

| 情绪 | valence | arousal | 情绪 | valence | arousal |
|---|---|---|---|---|---|
| 高兴 happy | +0.85 | +0.55 | 恐惧 fearful | −0.55 | +0.72 |
| 平静 neutral | +0.02 | −0.10 | 厌恶 disgusted | −0.68 | +0.30 |
| 惊讶 surprised | +0.30 | +0.85 | 悲伤 sad | −0.75 | −0.45 |
| 愤怒 angry | −0.62 | +0.78 | | | |

## 三、歌曲推荐算法

### 3.1 曲目特征来源（两条通道）

**A. 本地曲库 —— 真实声学分析（`js/dsp.js`）**

1. `AudioContext.decodeAudioData` 解码 → 下混单声道 → 取前 45 秒；
2. 分帧：帧长 2048、帧移 1024、Hann 窗，对每帧做基 2 迭代 FFT；
3. 帧级特征：RMS 能量、谱质心（频率加权幅度均值 / 总幅度）、过零率、谱通量；
4. **BPM**：谱通量做起始点包络 → 去均值半波整流 → 在 50~200 BPM 对应的时延区间做自相关，
   乘以中心 120 BPM 的对数正态先验抑制倍频/半频误判：
   `prior(bpm) = exp(−0.5·(log₂(bpm/120)/0.75)²)`；
5. **调式**：把 65~2100 Hz 的谱峰按 `pitch = 69 + 12·log₂(f/440)` 归入 12 维色度向量，
   与 Krumhansl-Kessler 大/小调轮廓做 12 次循环互相关，取最大者：
   `modeScore = clamp((ρ_major − ρ_minor) × 3.2, −1, 1)`；
6. **回归到情感环**：

```
energy     = clamp(RMS / 0.22, 0, 1)
brightness = clamp(log₂(1 + centroid/200) / log₂(1 + 6000/200), 0, 1)
tempoNorm  = clamp((BPM − 60) / 110, 0, 1)
arousal    = clamp(0.58·energy + 0.34·tempoNorm + 0.30·brightness − 0.42, −1, 1)
valence    = clamp(0.46·modeScore + 0.52·(brightness − 0.45) + 0.36·(energy − 0.45), −1, 1)
```

7. 情绪标签由特征**自动派生**（大调→healing、高唤醒→energetic、低频暗色→mellow 等），
   而不是人工硬编码，保证「标签与声音一致」；
8. 结果写入 `localStorage` 缓存，二次加载无需重新解码。

> 自测：120 BPM 的 C 大调合成信号识别为 117 BPM / C major；70 BPM 的 A 小调识别为 72 BPM / Am，
> 且两者 valence 分别为 +0.20 与 −0.47，方向正确。

**B. 在线曲库 —— iTunes Search API**

- 端点：`https://itunes.apple.com/search?term=…&media=music&entity=song&limit=…&country=…`
- 公开、免密钥、响应头 `Access-Control-Allow-Origin: *`，失败时自动降级为 JSONP；
- 中文关键词走 `country=hk`（国区无 30 秒试听），英文关键词走 `country=us`；
- 在线曲目缺少波形，用「曲风先验 + 标题/专辑关键词」推断情绪：
  `GENRE_PRIOR[genre]` 给出 (v, a, energy) 基线，命中 `MOOD_KEYWORDS` 时按 ±0.35·(1) 修正，
  `bpm` 由 arousal 反推：`bpm ≈ 62 + (a+1)/2 × 78`。

### 3.2 S1 目标情绪决策

| 策略 | 规则 | 适用 |
|---|---|---|
| 同频镜像 mirror | `target = (v, a)` | 共鸣式聆听、情绪强化 |
| 情绪修复 repair | `target = cur + 0.62·(anchor − cur)` | 消极情绪疏导 |
| 智能 auto | `v < −0.15 → repair`，否则 `mirror` | 默认 |

修复锚点 `anchor`：

| 当前主导情绪 | anchor (v, a) | 意图 |
|---|---|---|
| happy | (0.82, 0.62) | 保持并放大愉悦 |
| neutral | (0.55, 0.30) | 注入一点活力 |
| sad | (0.58, 0.10) | 先共情、再托举 |
| angry | (0.40, −0.15) | 降唤醒、泄压 |
| fearful | (0.45, −0.10) | 稳定安全感 |
| disgusted | (0.45, 0.05) | 转移注意力 |
| surprised | (0.60, 0.35) | 承接兴奋感 |

### 3.3 S2 五因子加权打分

```
S = 0.40·S_va + 0.22·S_emo + 0.18·S_rhythm + 0.11·S_pref + 0.09·S_quality
```

| 因子 | 公式 | 说明 |
|---|---|---|
| `S_va` 情感距离 | `exp(−d² / (2·0.42²))`，`d = √((Δv)²+(Δa)²)/√2` | 高斯核，σ=0.42；贴合约 0.6 个标准差内给高分 |
| `S_emo` 情绪标签 | `0.6·(命中标签数/需求标签数) + 0.4·sign(效价一致)` | sad→补 healing，angry/fearful→补 calm |
| `S_rhythm` 节奏能量 | `0.55·exp(−((BPM − BPM*) / 30)²) + 0.45·(1 − |energy − (a+1)/2|)` | `BPM* = 60 + (a+1)/2 × 82` |
| `S_pref` 偏好新颖 | `0.5 + 0.20·曲风命中 + 0.15·语种命中 + 0.25·已喜欢 − 0.45·已播放 − 0.80·不喜欢` | 新颖度惩罚避免重复推同一首 |
| `S_quality` 音源质量 | 本地 1.0；在线 0.86；无可用 URL ×0.2；时长 < 40s ×0.92 | 保证可播放性 |

对应 `js/recommender.js` 中的 `WEIGHTS`，权重集中在文件顶部，便于实验对比。

### 3.4 S3 MMR 多样性重排

贪心迭代选取：

```
pick = argmax_{t ∉ selected} [ λ · S(t)/S_max − (1 − λ) · max_{s ∈ selected} Sim(t, s) − 0.26·max(0, n_artist − 1) ]
Sim(t,s) = 0.55·[同一艺人] + 0.42·[同一曲风] + 0.15·(1 − |v_t − v_s| / 2)
λ = 0.75
```

- λ 越高越偏相关性，越低越偏多样性。避免「同一歌手的 8 首慢歌」占满歌单；
- 同一艺人的歌从第 3 首起每次递减 0.26 分（渐进惩罚，不搞一刀切）；
- 在线检索结果按**歌名**去重（同名翻唱/合集对体验弊大于利）。

### 3.5 可解释推荐理由

每首歌输出命中依据，例如：

- `情感坐标高度贴合（Δv=0.08, Δa=-0.12）`
- `标签命中「sad/healing」`
- `96 BPM 匹配当前唤醒需求`

界面上把五因子得分拆开展示（`scoreTitle` 悬浮提示），便于教学演示与答辩说明。

### 3.6 在线检索意图生成

按主导情绪 + 策略生成 2~3 组查询词，例如悲伤 + 修复 → `治愈 温暖` / `healing uplifting` / `温柔 慢歌`，
同时并行检索多区商店，按「歌名+艺人」去重，再进入统一打分。

### 3.7 自动播放触发逻辑（app.js）

歌单一经生成，立即自动播放得分第一的可播放曲目（`tryAutoPlay`）：

- **触发**：首次识别稳定（margin > 0.12 且置信度 > 0.42）后首推；实时模式下主导情绪变化且距上次推荐 > 6 s（防抖）；**静态图片只分析一帧，因此新图片识别命中不同情绪时跳过防抖立即重算**；
- **保护**：手动暂停后 30 s 内不再自动打断（点选新演示人脸 / 重新拍照即解除）；正在播放的曲目与新歌单第一名相同则不打断；
- **降级**：若浏览器自动播放策略拦截（`NotAllowedError`），显示「点击继续播放」提示条，一次点击即恢复；
- **开关**：「识别后自动播放」可随时关闭并持久化到 localStorage。

## 五、局限与可改进方向

1. **个体差异**：CNN 对夸张表情更敏感，平静/微表情易被判为 neutral；可加入个人校准（录制中性片段求基线）。
2. **类间混淆**：恐惧是最难的一类——模型常把「张口恐惧」误判为愤怒、把「瞪眼掩口」误判为惊讶
   （FER 数据集上恐惧样本少、与惊讶表情特征高度重叠所致）。制作演示素材时建议采用
   「眉毛上抬且向中间聚拢 + 瞪眼 + 紧张张口」的组合特征；7 张演示人脸已按此筛选并实测通过。
3. **几何先验的系数**是经验设定，若有标注数据可用逻辑回归重新拟合。
4. **在线曲目**缺少波形，情绪坐标为推断值；若接入带音频分析特征的 API（如 Spotify Audio Features）会显著更准。
5. **多脸场景**只取置信度最高的一张脸；可扩展为「主主体选择 + 多人共识情绪」。
6. 试听片段仅 30 秒，属于版权合规的预览形态，正式场景需接入授权曲库。
